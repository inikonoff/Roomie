# Changelog

История версий Cullect (до 2026-10-04 приложение называлось Roomie): что менялось и какие баги чинились, в хронологическом порядке (от
старых записей к новым). Новые записи дописываются в конец файла по мере выхода фиксов.

Каждая строка — один коммит в `main`: короткий хеш, тип (`Feature` / `Fix` / `CI` / `Tooling`)
и краткое описание сути изменения.

Отдельно отмечаются откаты (`Revert`), docs-правки (`Docs`) и осознанные изменения решений (`Change`). Для каждой записи важнее всего *почему*: какой симптом видел пользователь, какая причина найдена и какие гипотезы оказались неверными (они остаются в истории намеренно, чтобы не повторять).

## 2026-09-16 — Фикс фризов скролла по framestats

- `94e3836` **Fix** — найдена реальная причина многосекундных фризов при скролле сетки папок: по `dumpsys gfxinfo framestats` — 50-й перцентиль кадра 24мс, GPU-гистограмма показывала 7 кадров ~5с GPU-времени каждый, `GraphicBufferAllocator` держал ~71 МБ живых `AHardwareBuffer` размеров, точно совпадающих с превью. Coil по умолчанию декодирует через `HARDWARE`-битмапы (API 26+, GPU-буфер через gralloc IPC) — дёшево для одной долгоживущей картинки, дорого для десятков мелких тайлов, аллоцируемых/освобождаемых на каждый скролл. `MediaThumbnail` (единственное место декодирования превью — грид и обложки папок) теперь запрашивает `allowHardware(false)`; полноэкранное фото при свайпе (`SwipeCard`/`SwipeScreen`) не тронуто — там картинка одна и живёт весь просмотр, hardware-путь там уместен.

## 2026-09-16 — Стейл-грид после Trash, живой бейдж, прогрев зума, индикатор режима

- `1addc4c` **Fix/Feature** — гвард `loadedKey` в `FolderGridViewModel` (защищал от полной перезагрузки грида при каждом возврате Navigation Compose на экран) не замечал изменений в корзине: заход в Trash и обратно без выхода из папки целиком показывал уже удалённые тайлы. Теперь на каждый повторный вход сверяется ещё и дешёвый снимок `getTrashedStableIds()`, дорогой перезапрос идёт только если состав корзины реально изменился. У `TrashFolderScreen` убрано собственное подтверждение (`AlertDialog` перед "Очистить корзину") — это было лишним поверх системного диалога `createDeleteRequest`, кнопка теперь сразу вызывает `requestDeleteForever`. Бейдж корзины на экране свайпов показывал `deletedCount` (счётчик именно этой сессии) — после очистки корзины из середины сессии число оставалось прежним; добавлен `TrashDao.observeCount()`/`TrashRepository.observeTrashedCount()` (живой `Flow<Int>`), `SwipeSessionViewModel` подписывается на него в `trashedCount`, бейдж переключён на него (`deletedCount` не тронут — по-прежнему то, что показывают прогресс-бар и summary).
- `1addc4c` **Feature** — долгий зум на свежей карточке (первый long-press грузил полный размер с нуля) теперь прогревается в фоне: `SwipeCard` тихо зaпрашивает `Size.ORIGINAL` в кэш Coil, пока карточка просто видна незумленной (fire-and-forget, свайп раньше прогрева просто отменяет запрос вместе с `LaunchedEffect`). На экране свайпов под названием папки появилась подпись текущего режима (Classic/Browse) — `SwipeGesturePreset.label()` вынесена из приватной функции `SettingsScreen` в публичную рядом с самим enum, `SwipeSessionViewModel` вычисляет `gesturePreset` через уже существующий `SwipeGesturePreset.matching()`; подпись не показывается, если текущая комбинация свайпов не совпадает ни с одним пресетом.
- `e995ade` **Feature** — дисковый кэш готовых превью (эквивалент `DiskCacheStrategy.RESOURCE` из Glide): новый `ThumbnailDiskCache` хранит уже декодированную и уменьшенную битмапу под `cacheDir/thumb_cache`, ключ — хеш `uri + целевой размер`, так что попадание в кэш пропускает decode/downsample исходника целиком, а не просто повторно читает уже готовые байты. Фото-путь в `MediaThumbnail` при промахе ловит результат через Coil `listener`/`onSuccess` (`coil3.BitmapImage`) и пишет на диск в фоне, при попадании грузит файл напрямую вместо `uri`; видео-путь (`loadThumbnail`, объективно самый дорогой decode) сначала проверяет диск, при промахе пишет туда же. `SwipeCard` (полноэкранный просмотр) не тронут — у него уже свой кэш (Coil memory + сегодняшний прогрев зума). Эвикция и инвалидация при изменении исходного файла сознательно не входят в этот проход. В Settings (секция Cleanup) добавлена строка "Очистить кэш превью" с текущим размером (`SettingsViewModel.thumbnailCacheBytes`, живое состояние диска, не персистентная настройка) — тап чистит сразу, без диалога подтверждения (это только пересчитываемый кэш, не данные пользователя). Форматтер байт вынесен из `SummaryScreen` в `util/ByteFormat.kt`, чтобы не дублировать его для нового счётчика.

## 2026-09-17 — Холодный старт превью, скролл, скачок свайпа (проверка на устройстве)

Пользователь после вчерашних фиксов всё ещё видел на устройстве три симптома — новое ТЗ с шагами A-E, каждый отдельным коммитом.

- `22cb47e` **Fix (B)** — лимит параллельных декодов превью: фото-путь (через Coil) — `decoderCoroutineContext(Dispatchers.IO.limitedParallelism(3))` на общем `ImageLoader`; видео-путь (свой код, `loadThumbnail`) — `Semaphore(3)`. Пункт E (подскок при смене aspect ratio) проверен по коду — контейнер стека уже фиксированного размера с центрированием независимо от детей, `animateContentSize` нигде не используется; менять нечего, а сам репортнутый «подскок», возможно, и был проявлением именно гонки из пункта D.
