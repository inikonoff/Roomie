# Changelog

История версий Roomie: что менялось и какие баги чинились, в хронологическом порядке (от
старых записей к новым). Новые записи дописываются в конец файла по мере выхода фиксов.

Каждая строка — один коммит в `main`: короткий хеш, тип (`Feature` / `Fix` / `CI` / `Tooling`)
и краткое описание сути изменения.

## 2026-09-14 — Первая версия и стабилизация запуска

- `7fb50bc9` **Feature** — первая версия Roomie: галерея для свайп-уборки фото (Kotlin + Jetpack Compose), MVP.
- `6190e6df` **CI** — добавлен workflow сборки debug APK на каждый push.
- `5d9cce55` **Fix** — устранена неоднозначность перегрузки `items()` в `FolderListScreen` (ошибка сборки).
- `e7f718c3` **Feature** — добавлен `CrashReporter` для диагностики краша на реальном устройстве.
- `0290fd0f` **Fix** — перехват краша перенесён на более раннюю стадию запуска + автокопирование трейса в буфер обмена.
- `0bb79edf` **CI** — диагностика выравнивания страниц 16 КБ для нативных библиотек.
- `f8168cb8` **Fix** — убраны два подозрительных нативных `.so`, не дожидаясь диагностики.
- `3e342750` **Fix** — добавлены чекпоинты запуска, исправлено неверное предположение про `MainActivity`.
- `8fc13cb3` **Tooling** — добавлено минимальное probe-приложение для изоляции OS-level kill от бага самого Roomie.

## 2026-09-16 — Доводка удаления из корзины и плавности свайпа

- `1088103` **Fix** — протухшие (более не существующие в MediaStore) URI теперь отфильтровываются перед запросом `createDeleteRequest`, вместо того чтобы ронять его; добавлены диагностические чекпоинты `CrashReporter.mark(...)` по всему пути удаления.
- `0db1853` **Feature** — видимый прогресс ("N из M" + прогресс-бар) при очистке корзины, список уменьшается по одному файлу; выход с экрана заблокирован на время удаления.
- `035d91b` **Fix (CI)** — убран неверный импорт `weight` (резолвился на internal-декларацию), ломавший сборку.
- `146b1ef` **Fix** — записи корзины не удалялись из Room после подтверждённого системного удаления: `onDeleteConfirmed` повторно вызывал `resolver.delete()` на файл, который система уже стёрла сама при подтверждении `createDeleteRequest`, получал 0 и считал "не удалено". Теперь подтверждённое удаление просто синхронизирует Room, не трогая файл повторно.
- `dba28f5` **Fix** — плавность анимации свайпа: позиция карточки во время активного драга пишется синхронно (`mutableStateOf`), а не через `launch { snapTo(...) }` на каждое касание (это отставало от пальца на быстром свайпе); пружина возврата/вылета карточки сделана более собранной (`DampingRatioNoBouncy` + `StiffnessMedium` вместо `LowBouncy`/`StiffnessLow`); под топ-карточкой во время entrance-фейда теперь непрозрачная подложка на всю область стека, чтобы сквозь неё не проглядывала карточка позади при несовпадающей ориентации.
- `3cf5d9b` **Docs** — добавлен этот `CHANGELOG.md`, задним числом заполнен всей историей коммитов на тот момент.

## 2026-09-16 — Визуальный редизайн, проход 1/4

- `6d5c73d` **Feature/Fix** — первый из четырёх проходов визуального редизайна: `secondaryContainer`/`onSecondaryContainer`, `surfaceVariant`, `outline`, `onSurfaceVariant` теперь заданы явно вместо того, чтобы проваливаться в лавандовый дефолт Material3 (именно оттуда была лаванда на выбранном сегменте в Settings); фон сделан заметно темнее поверхности карточек; цвета чипов действий свайпа сделаны насыщеннее для контраста с новым `SelectedContainer`; подготовлены (но пока нигде не использованы) новые токены контейнеров чипов для прохода 2. `primary` и экраны `FolderListScreen`/`SwipeLimitScreen`/`SummaryScreen` не тронуты — вне охвата этого прохода. Заодно из Settings убран переключатель "Включить лимит свайпов и монетизацию" (только UI, логика `monetizationEnabled` не тронута).
- `5de75f1` **Feature/Fix** — фильтр периода переехал с главного экрана внутрь экрана конкретной папки (`FolderGridScreen`), и теперь запоминается отдельно на каждую папку (`SettingsRepository.getFolderPeriodFilter`/`setFolderPeriodFilter`, динамический ключ DataStore по bucketId); переход в свайп-сессию теперь читает актуальный фильтр из `FolderGridViewModel.uiState` в момент тапа, а не значение на момент входа в папку. "Хранение в корзине" — сегменты 1/3/7/30 заменены на выпадающий список с полным диапазоном 1-30 дней. Фаза 2 визуального редизайна: значения действий свайпа в Settings теперь цветные чипы с фоном-контейнером (`ActionChip`), а не голый цветной текст.
- `ab78539` **Fix/Feature** — обложки папок на главном экране рендерились через голый `AsyncImage` без целевого размера и часто декодировались в полном разрешении камеры; теперь используют `MediaThumbnail` (тот же компонент, что уже был в `FolderGridScreen`), `GalleryFolder` получил `coverIsVideo` для быстрого пути видео-превью. Заодно у плитки "Все фото" впервые появилась настоящая обложка — самый новый файл среди всех папок. Фаза 3 визуального редизайна (только компоновка): круглые иконки-стрелки перед каждым направлением свайпа, шеврон на всех тапабельных строках Settings (не на сегментах/свитчах), раздел "Жесты" теперь первый в списке вместо третьего.
- `fb0747e` **Fix** — та же лавандовая проблема (незаданные роли Material3), что была на выбранном сегменте до Фазы 1, оказалась и у `DropdownMenu` (роли `surfaceContainer*` вместо `surface`) — заданы явно. В Browse-режиме свайп влево с действием "Ничего не делать" подписан как "Предыдущее фото" (реальное поведение не менялось, только подпись). Пока активен пресет (Classic/Browse), строки Swipe right/left в Settings заблокированы (приглушены, без выпадающего меню) — правка left/right в обход пресета была как раз тем, из-за чего подсветка выбранного сегмента пропадала после ручной правки; Up/Down по-прежнему свободно редактируются в обоих режимах.
- `5811049` **Fix/Feature** — в Classic для Swipe up/down из списка выбора убраны Delete/Keep (уже заняты left/right), Browse не ограничен; Swipe right в Browse подписан "Next photo" вместо "Do nothing" (само действие осталось NONE, чтобы не сломать "Previous photo", которое читает `browseHistory`); подпись Postpone укорочена до "Postpone"/"Отложить" — не влезала в чип; все `TopAppBar` в приложении теперь красятся в `colorScheme.background`, а не в дефолтный `surface`, шапка сливается с фоном; видео-кэш увеличен с 64 до 300, у `ImageLoader` появился явный `memoryCache` (25% памяти приложения) — скролл по уже виденным превью ощущается быстрее.
- `8e9089d` **Fix** — найден точный баг потери подсветки Classic/Browse: `SwipeGesturePreset.matching()` сверял все 4 направления вместо только left/right (комментарий в коде уже описывал верное намерение, сама проверка — нет), поэтому правка up/down тоже сбрасывала пресет и разблокировала left/right. Сверка сужена до left/right. Отдельно — тот же класс бага, что чинили для экрана свайпов (`loadedSessionKey`): `FolderListViewModel`/`FolderGridViewModel` безусловно перезагружались при каждом возврате на экран (Navigation Compose пересоздаёт композицию), сбрасывая скролл списка папок и грида к началу — добавлены guard'ы (`hasLoaded`/`loadedKey`), повторный вход в уже загруженный список/грид теперь no-op.
- `9668c1d` **Chore** — убран модуль `:probe` (минимальная диагностическая Activity, добавленная на самых первых шагах проекта, чтобы отличить OS-level kill от краша самого Roomie) — задача давно решена, каждый CI-прогон впустую собирал и заливал вторую APK. Модуль, `include(":probe")` и шаги сборки/выгрузки в `build.yml` удалены; CI теперь собирает и выгружает только APK самого приложения.
- `5924e18` **Fix** — в Browse свайп влево на границе истории (первая карточка сессии) проваливался в общий код "пустого" свайпа — карточка уходила вперёд, а следующий свайп влево тут же тянул её назад, зацикливая A↔B. Теперь на границе `return` безусловный, плюс лёгкий вибро-клик как сигнал "дальше некуда". Отдельно — полная заливка всех ролей `ColorScheme` (primary/secondary/tertiary/error контейнеры и их "on"-цвета, surfaceTint/Bright/Dim, outlineVariant, inverse*, scrim) вместо точечных фиксов по одной роли за раз — это был уже третий случай, когда незаданная роль тихо падала на лавандовый дефолт Material3 (после `secondaryContainer` и `surfaceContainer` теперь всплыл `onPrimary` у кружка свитча).

## 2026-09-16 — Фикс фризов скролла по framestats

- `94e3836` **Fix** — найдена реальная причина многосекундных фризов при скролле сетки папок: по `dumpsys gfxinfo framestats` — 50-й перцентиль кадра 24мс, GPU-гистограмма показывала 7 кадров ~5с GPU-времени каждый, `GraphicBufferAllocator` держал ~71 МБ живых `AHardwareBuffer` размеров, точно совпадающих с превью. Coil по умолчанию декодирует через `HARDWARE`-битмапы (API 26+, GPU-буфер через gralloc IPC) — дёшево для одной долгоживущей картинки, дорого для десятков мелких тайлов, аллоцируемых/освобождаемых на каждый скролл. `MediaThumbnail` (единственное место декодирования превью — грид и обложки папок) теперь запрашивает `allowHardware(false)`; полноэкранное фото при свайпе (`SwipeCard`/`SwipeScreen`) не тронуто — там картинка одна и живёт весь просмотр, hardware-путь там уместен.
